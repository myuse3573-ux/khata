1. Executive Summary & Product Vision

Khata is a multi-platform, full-stack financial bookkeeping and shared community ledger application. It replaces error-prone paper ledgers (traditional Bahi-Khata) and chaotic flatmate spreadsheets with an intuitive, mobile-first digital experience.

The system solves two distinct financial workflows in a single cohesive platform:

  • Personal & Business Ledger: Complete double-entry customer credit (Udhar) and payment (Jama) management, daily cashbook expense registers, automated WhatsApp reminder dispatch, and instant vector PDF financial statement generation.
  • Collaborative Kitchen & Flatmate Ecosystem: Multi-user shared flat/hostel management featuring real-time Server-Sent Events (SSE), equal bill splitting with 1-click member ledger integration, and round-robin turn-tracker duty rosters (cooking, cleaning, groceries).
Core Architectural Principle: Data Domain Isolation
Khata enforces strict boundary separation between a user's Personal Ledger (private shop/individual transactions) and Shared Kitchen Groups (collaborative flatmate expenses). The two data domains are isolated in separate database collections, state contexts, and API endpoints, preventing any inadvertent data leakage.

5. Backend Architecture & API Security

The backend is powered by Express 5 running on Node.js 24. It adheres to REST architectural standards, stateless JWT session verification, and proactive defense-in-depth principles.

5.1 Authentication & Password Security

  • Bcrypt Password Hashing: Passwords are never stored in plain text. Every password is salted and hashed using bcryptjs with an industry-standard work factor of 12 rounds.
  • Legacy Password Migration: The authentication middleware automatically detects older legacy password strings, verifies them securely, and silently upgrades them to bcrypt hashes upon successful authentication without interrupting the user.
  • Stateless JWT Tokens: Upon authentication, an HMAC-SHA256 signed JSON Web Token is issued containing the user ID. Protected routes inspect the Authorization: Bearer <token> header.

5.2 Rate Limiting & Protection Against Abuse

To prevent brute-force attacks and credential stuffing, the server deploys two independent rate-limiting tiers via express-rate-limit:

  • authLimiter: Restricts registration, login, and password reset endpoints to a maximum of 15 requests per 15-minute window per IP address.
  • generalLimiter: Limits general API operations to 120 requests per minute, safeguarding against automated scraping or denial-of-service attempts.

5.3 Real-Time Server-Sent Events (SSE) Hub

Instead of introducing heavy WebSocket connection overhead, Khata utilizes lightweight Server-Sent Events (SSE) at GET /api/kitchen/:groupId/events to stream real-time updates to connected roommates: 

// Server-Sent Events implementation in server/server.js
const sseClients = new Map(); // groupId -> Set<Response>

app.get("/api/kitchen/:groupId/events", authenticateToken, requireKitchenMember(), (req, res) => {
  res.setHeader("Content-Type", "text/event-stream");
  res.setHeader("Cache-Control", "no-cache");
  res.setHeader("Connection", "keep-alive");
  res.flushHeaders();

  if (!sseClients.has(groupId)) sseClients.set(groupId, new Set());
  sseClients.get(groupId).add(res);

  // Periodic heartbeat every 30 seconds to maintain connection through NAT firewalls
  const heartbeat = setInterval(() => {
    try { res.write(": ping\n\n"); } catch { clearInterval(heartbeat); }
  }, 30000);

  req.on("close", () => {
    clearInterval(heartbeat);
    sseClients.get(groupId)?.delete(res);
  });
});

6. Frontend Architecture & State Management

Khata's frontend is constructed using React 19, Vite 8, and Tailwind CSS 4. The design philosophy centers around high responsiveness, tactile mobile feedback, and clear domain separation.

6.1 Triple Context Architecture

To prevent monolithic state bloat and eliminate unwanted cross-component re-renders, application state is divided into three distinct React Context layers:

1. AuthContext Security

Manages user authentication lifecycle, JWT token persistence in LocalStorage, login/register mutations, and the client-side PIN security lockscreen (isLocked).

2. PersonalContext Ledger

Encapsulates private shop/individual ledger data: customer records, udhar/jama transactions, daily cashbook, and business profile. Employs user-scoped localStorage keys (khata_{userId}_{key}) for offline reliability.

3. KitchenContext Realtime

Manages collaborative kitchen groups, roommate memberships, duty rosters, and shared cashbook expenses. Subscribes to the live SSE stream with an automatic heartbeat and fallback polling mechanism.

4. Offline-First Resilience Reliability

If network connectivity drops or the cloud server is unreachable, the app automatically transitions to local cache mode, rendering an amber status banner while queuing changes for synchronization.

6.2 Core UI View Hierarchy & Routing

Rather than relying on bulky URL routers that add bundle size in mobile environments, Khata utilizes a responsive state-driven view controller within src/App.jsx:

7. Core Business Logic & Algorithms

7.1 Double-Entry Balance Calculation Engine

At the heart of Khata is the balance calculation algorithm implemented in src/utils/formatters.js. For any customer account, transactions are categorized into two types:

  • Gave (Udhar): Credit extended to the customer (they owe you money).
  • Got (Jama): Payment received from the customer (they paid you money).
export const calculateCustomerBalance = (transactions = []) => {
  let totalGave = 0; // Udhar given by shopkeeper
  let totalGot = 0;  // Jama paid by customer

  for (const tx of transactions) {
    const amt = Number(tx.amount || 0);
    if (tx.type === "gave") totalGave += amt;
    else if (tx.type === "got") totalGot += amt;
  }

  const diff = totalGave - totalGot;

  if (diff > 0) {
    return { balance: diff, status: "get" };     // Shopkeeper will collect money (Asset)
  } else if (diff < 0) {
    return { balance: Math.abs(diff), status: "give" }; // Customer has advance credit (Liability)
  }
  return { balance: 0, status: "settled" };      // Account is fully settled
};

7.2 Turn Tracker Round-Robin Rotation Algorithm

In shared flats or hostel groups, roommates share duties such as cooking, grocery shopping, or water can refills. The turn progression algorithm guarantees fair rotation while skipping members who are temporarily marked as paused (e.g. traveling or on leave): 

function advanceDutyTurn(dutyItem, members) {
  const activeMembers = dutyItem.memberIds
    .map(id => members.find(m => m.id === id || m.userId === id))
    .filter(m => m && m.status !== "paused"); // Skip absent/paused roommates

  if (activeMembers.length === 0) return dutyItem;

  const nextIndex = (dutyItem.currentTurnIndex + 1) % activeMembers.length;
  const currentPerson = activeMembers[dutyItem.currentTurnIndex % activeMembers.length];

  return {
    ...dutyItem,
    currentTurnIndex: nextIndex,
    lastBroughtBy: currentPerson.name,
    lastBroughtDate: new Date().toISOString(),
    history: [
      { person: currentPerson.name, date: new Date().toISOString() },
      ...(dutyItem.history || [])
    ]
  };
}

7.3 Shared Bill Splitting & Ledger Auto-Injection

When an expense occurs in a kitchen group (e.g. a ₹1,200 grocery bill), the split calculator automatically computes the per-person liability (Math.round(total / count)) and gives the user the option to automatically log an Udhar transaction into each member's personal ledger with a single click.

7.4 Dynamic UPI Intent & QR Code Protocol

Khata integrates the standard National Payments Corporation of India (NPCI) UPI Intent specification. In QRPayView.jsx, payment links are assembled according to the standard URI scheme: 

upi://pay?pa={merchantUpiId}&pn={encode(businessName)}&am={amount}&cu=INR&tn={encode(note)}

This URI is fed directly into qrcode.react to generate a crisp vector QR code compatible with Google Pay, PhonePe, Paytm, BHIM, and all mobile banking applications.

7.5 Client-Side Vector PDF Engine (jspdf + jspdf-autotable)

Unlike apps that rely on slow server-side rendering pipelines (like Puppeteer), Khata renders complete financial statements directly in the browser using client-side JavaScript. This enables instant statement generation even when completely offline:

  • Creates branded vector headers with merchant business name, address, GSTIN, and phone number.
  • Calculates summary boxes highlighting net receivables vs. payables.
  • Constructs styled data tables with alternating row shading, date formatters, and totals footers.
  • Exports clean, print-ready PDF files directly into the user's downloads folder.

8. Mobile Native Shell & Packaging (Android APK)

Khata is engineered to run seamlessly as both a responsive web application and a native Android APK. This is achieved using Capacitor 6.

8.1 Capacitor Bridge Architecture

Capacitor bridges the React web bundle (dist/) inside a native Android WebView wrapper, providing native runtime performance without requiring a separate React Native rewrite:

  • capacitor.config.json: Declares the native package ID (com.khata.app), application title, and assets source directory.
  • android/ Directory: Fully configured Android Studio project featuring MainActivity.java and Gradle build scripts.
  • Hardware Permissions: Android manifest enables camera access (android.permission.CAMERA) for scanning UPI and invite QR codes, alongside storage and network state permissions.

8.2 Automated 3-Stage APK Build Pipeline

Building the Android APK is entirely automated via Build-Android-APK.bat: 

# Stage 1: Build production web bundle via Vite
call npm run build

# Stage 2: Sync web assets into native Android directory
call npx cap sync android

# Stage 3: Compile debug APK via Gradle Wrapper
cd android
call gradlew.bat assembleDebug

# Output APK: android/app/build/outputs/apk/debug/app-debug.apk
